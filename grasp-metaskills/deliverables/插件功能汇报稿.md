# 通用技能执行插件汇报稿

> 约 3 分钟

各位领导，今天汇报一下通用技能执行插件的建设情况。

我们主要解决三个问题：现有 AI 能力比较分散，复杂任务往往靠人工串联；执行过程不够透明，出现问题难以追溯；更换模型或运行平台时，业务流程容易重复开发。

针对这些问题，我们基于 GraSP 和 MetaSkills 的核心机制，完成了 Python 重构与整合。整个系统采用 Python 3.11，作为源码模块接入，支持本地函数和 MCP 工具，不绑定特定的智能体平台，也没有 JavaScript 或 Rust 核心运行时依赖。

插件的工作方式是：先管理好可复用的技能，再根据任务组织流程，通过工具完成执行，最后验证结果并保留记录。

其中，Skills 模块负责技能导入、检索、版本和依赖管理。已有技能可以通过配置文件批量导入，正文和附件都会形成版本快照；业务人员或开发人员调整技能后重新导入，不会覆盖历史版本。

Meta 模块负责把任务转化为候选计划。它通过可替换的模型接口工作，选择已提供的技能及其版本，不直接操作业务系统。随后，图执行模块检查计划的前置条件、数据类型和依赖关系，把通过检查的计划组织成执行图。业务规则仍需要明确写入技能契约，不能只依赖模型自行理解。

Tools 模块负责实际调用，包括注册的 Python 函数，以及配置的 MCP 服务。四部分通过清晰接口协作，技能管理、工具调用和任务规划也可以独立使用，方便接入不同的运行环境。

执行过程中，系统支持独立节点并发、超时和取消、结果缓存、状态持久化和中断恢复。在配置修复引擎后，可以对失败节点及受影响的子图进行局部修复，复用不受影响的有效结果。每一步的结果和验证记录都有迹可查。

以金融、法律领域的模型评测为例，后续可以把数据加载、被测模型调用、领域评分和报告汇总做成业务技能，复用这一套执行底座。两类业务主要调整评分技能、数据和规则，不需要分别重建调度系统。被测模型答错应当记录为评测结果，而不是通过流程修复把答案改对。

当前已完成模块实现和自动化回归，并验证了真实 MCP 连接及配置到执行的完整链路。需要明确的是，这些验证证明了工程链路的可用性，不代表已经完成金融、法律业务落地，也不代表模型规划质量已经达标。

下一步建议选取一项真实评测任务，补齐数据、评分标准和工具绑定，再验证规划质量、执行稳定性与接入成本，为后续扩展提供依据。
