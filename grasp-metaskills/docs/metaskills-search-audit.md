# MetaSkills search source audit

Only the MIT checkout at `dcd3fb55cabb438dc200f9b7c784ca14c08135ce` was read. `git rev-parse HEAD` verified that revision before extraction. No later revision was consulted. This module ports the actual source algorithms rather than substituting a vector database, third-party embedder, or generic RRF package.

`embeddings_local.rs` is explicitly an ONNX placeholder: construction fails and availability is false. No local ML inference is claimed or fabricated. The upstream API transport is not copied; the existing project provider boundary can supply real API embeddings while the deterministic hash implementation remains available.

`context.rs` does **not** implement a recent-skill, cwd, or tech-stack ranking boost. No such heuristic was added. The files audited here also do not implement BM25; fusion accepts already-ranked lexical results. Integration should supply the registry's lexical ranking, not call this module a BM25 implementation.

## Explicit compatibility decisions

* Rust f32 arithmetic is reproduced using standard-library struct pack/unpack after each arithmetic operation, including accumulation, square root, normalization and fusion. No rounding to a chosen decimal precision is introduced.
* Rust `char::is_alphanumeric` uses Unicode Alphabetic/Number semantics, which differ from Python `str.isalnum` for combining marks. The embedded interval table was generated offline by enumerating that Rust predicate over all Unicode scalar values with the same rustc version used for the harness. This avoids an incorrect ASCII-only or Python-only tokenizer. Unicode data versions of an older upstream Rust compiler can differ for newly assigned characters. Lowercasing uses Python Unicode lowercase; the common scripts and golden examples match, but differing runtime Unicode versions can affect newly assigned characters.
* Source HashMap iteration makes exactly tied scores nondeterministic. Python preserves first-seen/insertion order for ties; no new score or secondary ranking criterion is introduced. Do not assert upstream tie order.
* `HashEmbeddingProvider.embed(texts)` is a batch adapter to the existing provider protocol; the original Rust embed method takes one string. `hash_embedding` exposes the original single-text behavior, including zero dimensions returning an empty vector. Negative dimensions/limits are not representable in Rust usize: Python rejects negative dimensions and treats negative result limits as zero.
* Filter lookup helpers deliberately accept mapping records with source field names (`metadata_json`, `source_layer`, `quality_score`, `is_deprecated`). The registry should construct those explicit fields from its metadata rather than infer layer from arbitrary filesystem paths.

## Integration

Use `HashEmbeddingProvider(dims=384)` where an `EmbeddingProvider` is expected. Use `VectorIndex(dims)` for upstream dot-product ranking, then `fuse_results(lexical_pairs, semantic_pairs, RrfConfig())`. Apply `filter_hybrid_results` to the fused candidate set before the final user-facing truncation. Preserve candidate pool size decisions in the caller. The explicit module avoids coupling the source algorithms to registry persistence or the application's Skill contract.

## Registry integration delivered

`SkillRegistry` defaults to the offline `HashEmbeddingProvider`; explicitly passing `embedding_provider=None` disables semantic/hybrid search. External providers remain injectable. Registry hybrid search invokes the ported f32 `fuse_results`; structured filters use the ported `SearchFilters` **after** fusion and before result truncation. Unrecognized filter keys retain the registry's generic equality/membership behavior. Skill metadata supplies tags, source_layer/layer, quality_score/quality, and is_deprecated/deprecated; missing layer defaults to project and missing quality to zero as an explicit adapter policy. SQLite FTS5 still owns lexical candidate retrieval and its BM25 implementation.

Integration tests use the actual SQLite registry, default offline semantic retrieval, source RRF equality, source filter aliases/OR tags/quality/deprecation, SQLite reopening and JSON import/export ranking equivalence, compiler discovery and durable feedback replay. Combined affected test run: 28 passing. Four involved source modules pass strict mypy; Ruff checks pass.
