# 通用失败恢复与局部修复

适用 `plugin_manager/plugins/graph/` 文件模块。实现通用机制，不预置金融、法律、补题或修题规则，不调用模型编造修复方案。

## 配置

在 `config/plugin.json` 设置 `repair_enabled: true`，并填写 `repair_policy`。默认关闭；即便启用，空规则也只记录失败，不会自行猜测修复方式。

```json
{
  "repair_enabled": true,
  "repair_policy": {
    "max_decisions": 8,
    "max_node_attempts": 2,
    "max_same_failure": 2,
    "max_added_nodes": 3,
    "max_added_edges": 5,
    "rules": [
      {
        "name": "retry-temporary-service-failure",
        "reason_codes": ["service_busy"],
        "categories": ["execution"],
        "action": "retry",
        "max_attempts": 2
      },
      {
        "name": "replace-failed-capability",
        "reason_codes": ["capability_unavailable"],
        "action": "patch",
        "operators": ["Substitute"],
        "max_attempts": 1
      }
    ]
  }
}
```

以上是总配置的局部片段，保留已有 Skills、状态和 MCP 等路径配置。

规则按顺序匹配，第一条命中即决定处理方式。`reason_codes` 与 `categories` 同时存在时必须同时满足；空选择器匹配任意失败，宽泛规则应放在最后。`action` 为 `retry`、`patch` 或 `stop`。

## 结构化失败

工具返回节点结果时，可报告失败，不必伪造成功输出或成功效果：

```python
return {
    "output": {},
    "failure": {
        "category": "gate",
        "reason_code": "insufficient_items",
        "message": "有效条目数量不足",
        "affected_items": ["item-2", "item-9"],
        "details": {"required": 100, "actual": 98}
    }
}
```

这只是报告格式，不代表已实现补齐能力。业务侧负责产生真实失败报告并配置相应策略。失败结果不发布 `observed_effects`，不接受为成功节点；成功输出仍按既有输入输出和效果验证。

自定义 `SkillVerifier` 也可返回 `VerificationResult(passed=False, category=..., details={"reason_code": ..., "affected_items": [...], "details": {...}})`。普通执行异常使用 `execution` 错误码；执行超时使用 `timeout`。错误消息不用于模糊匹配规则。

## 重试和预算

- `retry` 仅允许技能元数据明确为 `"idempotent": true` 的失败节点。
- 在 `contract.json` 的 `metadata` 中声明幂等性前，业务代码必须真正支持安全重复调用；该声明不会自动实现幂等。
- 重试不修改 DAG 版本；清空失败节点及其下游的结果和缓存，保留无关节点的有效结果，并重新计算已确认事实。
- `patch` 使用既有五种 GraSP 操作：`InsertPrereq`、`Rebind`、`Substitute`、`Rewire`、`Bypass`。规则必须显式列出允许操作，没有新的伪 GraSP 操作。
- 局部修图重新验证无环性、前置条件、依赖及输入输出契约，成功后生成新图版本，并按受影响子图重执行。
- `max_decisions` 限制整张图的恢复尝试次数，包括被拒绝的尝试；`max_node_attempts` 限制单节点累计尝试，另外仍受节点原有 `repair_budget` 限制。
- `max_attempts` 是同一节点、同一规则的尝试上限。`max_same_failure` 是连续相同类别和错误码允许尝试恢复的次数；达到后下一次失败终止。节点成功后清除连续失败计数，但不清除累计预算。
- 策略启用时，恢复策略接管重试，运行时不再执行旧的无条件 `retries` 循环，防止绕过预算。未启用时保留原有行为。
- 所有计数与决策随 GraphState 持久化，重新创建运行时不会清空预算。
- 取消或结果未知不自动修复。非幂等执行超时保持 `outcome-unknown`，需要调用方核对外部结果；不能靠更换 Skill 绕过核对。

无规则、预算耗尽、无合法候选或策略异常均停止当前失败链；无关可执行分支可继续，最终报告反映失败。此时由 Harness 展示失败并决定是否补充输入或另开任务，本模块不主动发起用户交互。

## 保护节点

可在必须保留的技能元数据中声明：

```json
{"metadata": {"repair_protected": true}}
```

策略层拒绝绕过、替换或重新绑定保护节点，并禁止减弱它到原下游的顺序关系。保护节点如果明确幂等，可以重试。

此保护针对已在图内的节点，不是完整的业务强制闸门编译规则。哪些闸门必须出现在初始图中、何时允许交付，仍需业务约束接入。

## 自定义修复提案

复杂情况可实现同步 `RepairStrategy.propose(graph, state, failure, rule)`，返回最多 8 个候选 `RepairOperation`；候选按顺序验证，选择第一个合法操作。每次只提交一个操作，失败后重新执行与验证。

通过 `Plugin(repair_strategy=strategy)` 或 `Plugin.from_config(..., repair_strategy=strategy)` 注入。策略收到快照，不应执行工具、写文件或修改外部状态。需要异步模型推理的策略不在本次同步接口范围内。

```python
from plugin_manager.plugins.graph.contracts import RepairOperation

class SubstituteStrategy:
    def __init__(self, candidate):
        self.candidate = candidate

    def propose(self, graph, state, failure, rule):
        return [RepairOperation(
            type="Substitute",
            node_id=failure.node_id,
            replacement=self.candidate,
            args=[]
        )]
```

`candidate` 必须是注册表中真实存在且一致的技能快照；有契约参数时需要给出正确 `args`。提案不能添加虚构技能、跳过操作白名单或绕过图校验。未注入策略时，按允许的 GraSP 操作从现有注册表选择候选。

## 审计与边界

`status()` / `run()` 报告的 `repair_audit` 保存匹配规则、动作、失败类别与错误码、相关条目、停止原因及图版本。`trace` 包含 `recovery_decision`；底层修图审计包含具体操作、受影响节点和旧节点快照。

当前机制按节点失效与重执行。只修复某几个条目，需要工具支持按 ID 修订、合并及去重；`affected_items` 不会自动实现这些业务能力。工具是否幂等、哪些失败可修复、修复结果是否符合业务要求，都需要真实业务接口及验证器。
