# graph 插件调用说明

适用 Python 3.11+。本文以 `plugin_manager/` 文件夹为边界，示例默认其父目录在 Python 模块搜索路径中。插件以 Python 异步函数调用，不提供独立 HTTP 服务或 MCP 服务端；MCP 能力是客户端连接外部工具。

## 1. 安装与导入

在 `plugin_manager/` 的父目录安装依赖：

```bash
python -m pip install -r plugin_manager/plugins/graph/requirements.txt
# 需要连接 MCP 时额外安装
python -m pip install -r plugin_manager/plugins/graph/requirements-mcp.txt
```

统一导入入口：

```python
from plugin_manager.plugins.graph.api import Plugin
```

## 2. 通过 Manager 调用

Manager 默认读取自身 `config/plugins.json`，只注册工厂，启动时才导入子插件。graph 使用自己的配置。禁用某项设置 `enabled: false`；新增子插件放入 `plugin_manager/plugins/<type>/api.py`，提供 `Plugin` 工厂及 `start`、`invoke`、`aclose` 接口，并在配置中添加对应名称和类型。类型只接受单个 Python 模块标识符。

```python
from plugin_manager import PluginManager

async def main():
    async with PluginManager() as manager:
        await manager.start_all()
        result = await manager.call("graph", "tools.list", {})
```

`start_all()` 按注册顺序启动，失败或取消时逆序清理本批启动的插件，保留原先已运行的实例。`load_builtin=False` 跳过默认配置，供完全手动注册使用。配置可选 `config_file` 指向子插件配置，相对 Manager 配置文件目录解析。手动 `start/stop/unregister` 不能修改正在启动批次中的条目。

### 单独调用 graph


```python
import asyncio
from plugin_manager.plugins.graph.api import Plugin

async def main():
    async with Plugin() as plugin:
        print(await plugin.call("tools.list"))

asyncio.run(main())
```

`Plugin()` 自动读取`config/plugin.json`，不依赖当前工作目录。进入异步上下文时创建注册表、导入 Skills、注册本地工具、连接 MCP；退出时取消并等待活动调用，关闭连接并释放注册表。

需要显式管理生命周期时：

```python
plugin = Plugin()
await plugin.start()
try:
    result = await plugin.call("tools.list")
finally:
    await plugin.aclose()
```

也可以用 `Plugin.from_config("plugin_manager/plugins/graph/config/plugin.json")` 指定配置。

## 3. 任务检查与自然语言执行

任务检查已移到同级独立 `task` 子插件。Graph 不导入 Task，不读取模板，也不返回 `needs_input`。Harness 需要需求检查时，先调用 Task，再传递它的 `request`：

```python
from plugin_manager import PluginManager

async with PluginManager() as manager:
    await manager.start("task")
    checked = await manager.call("task", "check", {
        "task": "本次任务的自然语言描述",
        "task_data": {"objective": "完成任务", "inputs": {}}
    })
    if checked["status"] == "ready":
        await manager.start("graph")
        result = await manager.call("graph", "prepare", checked["request"])
    else:
        issues = checked["issues"]  # 一次收集全部问题，由 Harness 组织询问
```

模板新增与任务接口见 [任务模板指南](../../task/docs/任务模板指南.md)。Task 无模型或工具依赖；两插件不直接调用。已完整的请求可直接交给 Graph。自然语言请求的 `task_data` 仅作为 Meta 上下文，不能代替节点输入；显式目标模式不进行模板校验；其中 `context` 仅用于规划，直接编译时会在检查其类型后移除。

### 自然语言执行

```python
async with Plugin() as plugin:
    result = await plugin.run({"task": "读取待评测结果，执行检查并汇总报告"})
```

未提供 `goal` 时，插件调用 Meta，使用配置的 LLM 生成计划，再编译、验证并执行技能图。任务可以用自然语言，但必须有对应的 Skills、显式契约、工具和业务数据。以上描述是调用示例，不代表插件自带评测业务。

当前 Meta 使用全部已注册 Skills 作为候选，不是在规划前按任务检索筛选。模型配置缺失、计划无效或能力不足会报错。

## 4. 显式目标执行

```python
async with Plugin() as plugin:
    result = await plugin.run({
        "goal": ["report_ready(job1)"],
        "initial_conditions": ["data_ready(job1)"]
    })
```

只要请求包含 `goal` 字段，便跳过 Meta，直接编译并执行。目标和初始条件是技能契约中的事实表达式，不是自然语言；例子中的事实需要由实际技能契约支持。不要把尚未确认的状态当成初始事实。

执行请求字段：

| 字段 | 含义 |
|---|---|
| `task` | 任务描述，显式目标模式可省略 |
| `goal` | 目标事实列表 |
| `initial_conditions` | 已知成立的初始事实列表 |
| `inputs` | 按图节点 ID 组织的输入字典，不是任意扁平业务参数 |
| `proposal` | 可选技能选择提案 |
| `order_hints` | 可选顺序约束 |

自然语言规划请求另支持 `context` 字典；显式目标执行请求不支持该字段。请求采用严格校验，不接受未声明字段。

## 5. 先规划、后编译和执行

只生成计划，不执行工具：

```python
planned = await plugin.plan({"task": "执行任务"})
# planned["plan"] 是计划；planned["request"] 是编译请求
prepared = await plugin.prepare(planned["request"])
result = await plugin.execute(prepared["graph_id"])
```

`plan()` 不保证图已经通过编译。`prepare()` 才编译、验证并持久化执行图，不执行技能工具。

也可以直接先编译：

```python
prepared = await plugin.prepare({"task": "执行任务"})
graph_id = prepared["graph_id"]
result = await plugin.execute(graph_id)
```

`prepare()` 未提供 `goal` 时，同样先调用 Meta。

## 6. 状态、取消与恢复

```python
status = await plugin.status(graph_id)
cancelled = await plugin.cancel(graph_id)
recovered = await plugin.resume(graph_id)
```

`run()` 和 `execute()` 会等待执行结束；若需执行过程中查询或取消，由调用方通过 `asyncio.create_task()` 启动执行，再在另一个协程调用状态或取消接口。

`cancel()` 返回 `cancel_requested`，表示是否对本插件实例中的活动执行发出了取消请求。它不能跨进程控制另一实例。

恢复使用`state/runs/` 文件中的执行图和结果。对于执行结果未知的节点，默认不冒险重试；明确接受重复副作用风险时才调用 `resume(graph_id, retry_unknown=True)`。

执行报告主要字段：`graph_id`、`graph_version`、`status`、`outputs`、`errors`、`verification`、`repair_audit`、`trace`。`outputs` 按成功节点 ID 组织；检查 `status` 和 `errors`，不要把拿到字典当作任务成功。异常可能直接抛出，不保证都转换为报告。

## 7. 通用操作入口

`call(operation, payload)` 与 `invoke(operation, payload)` 等价。便捷方法最终也调用同一入口。

```python
tools = await plugin.call("tools.list")
result = await plugin.call("tools.call", {
    "name": "add",
    "arguments": {"a": 2, "b": 3},
    "timeout": 10
})
print(result["data"])
```

`add` 必须已注册。直接工具调用不经过技能图编译、技能效果验证或图修复。

公开操作：

- 图操作：`plan`、`run`、`prepare`、`execute`、`status`、`cancel`、`resume`。
- 工具操作：`tools.list`、`tools.call`。
- 技能操作：`skills.register`、`skills.search`、`skills.get`、`skills.reload`、`skills.dependencies`、`skills.compose`、`skills.delete`、`skills.export`、`skills.import`。

例如：

```python
found = await plugin.call("skills.search", {
    "query": "报告", "mode": "keyword", "limit": 10
})
loaded = await plugin.call("skills.import", {
    "config": "plugin_manager/plugins/graph/config/skills.json"
})
```

## 8. 插件内部配置

配置和对应 Schema 统一位于 `plugin_manager/plugins/graph/config/`，共 `plugin`、`meta`、`skills` 三组 JSON 文件。修改配置文件即可；Schema 文件用于校验，不填写业务配置。

### 总配置：config/plugin.json

配置文件路径以 `config/plugin.json` 所在目录为基准。核心路径配置：

```json
{
  "skills_dir": "../skills/library",
  "state_dir": "../state",
  "skills_file": "skills.json",
  "tools_config_file": "../../../../tools/config/gateway.json",
  "meta_file": "meta.json"
}
```

技能直接从 `skills/library/` 加载，不再使用 SQLite。运行记录保存在 `state/runs/`。旧的 `database` 配置字段、技能版本参数、`skills.history` 和 Git 技能归档均已移除；原 SQLite 数据不自动迁移，也不删除原数据库文件。

### LLM：config/meta.json

把默认的 `"llm": null` 改为实际连接配置，保留其他现有字段：

```json
{
  "llm": {
    "base_url": "http://127.0.0.1:8000/v1",
    "model": "实际模型名称",
    "api_key_env": "MODEL_API_KEY",
    "timeout": 30
  }
}
```

支持 OpenAI 兼容 Chat Completions 接口；自动在 `base_url` 后追加 `/chat/completions`。密钥由 `MODEL_API_KEY` 环境变量提供，不写进 JSON。无鉴权时设置 `"api_key_env": null`。Harness 不需要传模型客户端。

### 工具模块：../../../tools/

`plugin_manager/` 与 `tools/` 为同级目录，graph 位于 `plugin_manager/plugins/graph/`。插件通过 `config/plugin.json` 的 `tools_config_file` 加载独立工具网关配置；预置工具、MCP 和监控由网关统一管理。网关配置位于 `../../../tools/config/gateway.json`，其中 `mcp_file` 和 `monitor_file` 相对网关配置目录解析。

### 本地工具：../../../tools/builtin/

在 `../../../tools/builtin/your_tools.py` 中写同步或异步函数，并在该目录 `__init__.py` 中导入、加入已有 `BUILTIN_TOOLS`：

```python
from .your_tools import add
BUILTIN_TOOLS["add"] = add
```

启动时自动注册，Harness 无需传 `functions`。不是自动扫描所有函数；新增工具需要明确加入映射。修改代码后重启插件所在进程。

参与技能图执行的工具必须返回 `NodeResult` 结构，例如：

```python
return {"output": {"path": report_path}, "observed_effects": ["report_ready(job1)"]}
```

只在实际确认效果成立后返回对应 `observed_effects`。普通整数或字符串可以用于直接工具调用，但不能作为图执行的节点结果。

### MCP：独立模块 ../../../tools/config/mcp.json

```json
{
  "mcp_servers": {
    "business": {
      "command": "python",
      "args": ["/path/to/mcp_server.py"],
      "allowed_tools": ["search"]
    }
  }
}
```

独立工具模块当前支持 stdio MCP；不支持 Streamable HTTP 或 SSE。启动时连接并发现工具，工具名为 `business.search`；参数必须符合外部工具的实际 Schema。

### Skills：skills/library/ 与 config/skills.json

默认扫描 `skills_dir` 指定的技能目录。每个技能一个子目录：

```text
skills/library/
└── finish/
    ├── SKILL.md
    └── contract.json
```

`SKILL.md` 编写说明与工作流程，可用 YAML frontmatter 填写名称、描述等元数据。`contract.json` 显式填写可执行契约：

```json
{
  "id": "finish",
  "name": "完成任务",
  "description": "完成工作并确认结果",
  "tool": "finish",
  "dependencies": [],
  "contract": {
    "params": [],
    "preconditions": [],
    "effects": ["done(x)"],
    "input_schema": {"type": "object", "additionalProperties": false},
    "output_schema": {"type": "object"}
  }
}
```

`finish` 工具必须已经注册，并返回对应的 `output` 和实际成立的 `observed_effects`。仅写自然语言流程不等于可执行契约。依赖可用技能 ID 字符串或 `{"id": "other_skill"}`，不支持版本约束。

编辑文件后调用：

```python
await plugin.call("skills.reload")
```

刷新完整校验后一次替换内存目录；缺失依赖、循环依赖、重复 ID 或格式错误时保留上一次成功加载的目录。已准备或运行中的执行图保留自己的技能快照，不受刷新影响。新增技能也可通过 `skills.register` 写入主技能目录；已存在的技能通过编辑源文件更新，不维护旧版本。`skills.delete` 停止加载对应技能，辅助资源文件保留，外部技能目录由调用方直接管理。

需要加载主目录以外的技能时，使用 `config/skills.json`：

```json
{
  "skills": [{"path": "../another_skill_library", "recursive": true}]
}
```

路径相对该配置文件。`skills.import` 增加本实例内的加载来源；需要重启后仍加载时，应写入该配置文件。空列表不影响默认主技能目录加载。

### 执行记录与恢复

```text
state/runs/<run_id>/
├── run.json     # 权威提交文件：图快照、状态、反馈
├── graph.json   # 执行图与技能定义快照
├── state.json   # 节点状态、结果和验证、修复记录
└── trace.jsonl  # 按时间排列的事件
```

`run.json` 原子替换提交，其他文件是可重建的阅读视图；恢复时以 `run.json` 为准，并重建视图，避免崩溃造成图和状态不一致。OS 文件锁避免不同实例同时执行同一运行，进程退出后锁自动释放。锁文件需保留，不要在执行中删除。

调用链通过运行 ID、节点 ID、工具名和调用 ID 关联，记录尝试、耗时、结果持久化、验证、失败和局部修复。运行图包含本次技能内容和资源快照，不构成可查询的技能版本库。图的 `graph_version` 仅表示同一次运行中局部修复的图修订号。

运行记录包含结果及技能资源，可能包含业务数据，应由调用方控制存储目录权限和保留周期。当前不提供 SQLite 自动迁移、旧技能版本查询或跨机器分布式锁。默认本地哈希嵌入无需云服务；关键词/全文搜索改用内存 BM25，排序不保证与旧 SQLite FTS5 完全相同。

## 9. 接入职责

Harness 负责提供任务、必要输入和生命周期管理。插件内部负责配置加载、技能存储、Meta 规划、图编译、工具调用、验证和执行记录。不依赖特定 Harness 或其插件接口；接入时确保 `plugin_manager/` 的父目录在 Python 模块搜索路径中。
